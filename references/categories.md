# 六类问题的判定细则

每类都按同一个结构写：它是什么、常见信号、去哪找证据、怎么判档、常见误报。

判档只有三档：

- **有据**：在用户给的材料里找到了出处，能指到文件和行号，或者表格里的某一格。
- **存疑**：材料里找不到，但也找不到反证。外部事实（行业数据、别家产品的情况）在不联网时一律归这一档。
- **无据**：材料里有反证；或者说的是用户自己的东西（文件、功能、数据），材料里本该有，却找不到。

拿不准的时候判「存疑」，不判「无据」。冤枉一条真话，比放过一条可疑的话代价更大。

---

## 1. 演示数据冒充实测

**是什么**：原型里的示例数字、设计目标、假设的场景，被写成了已经发生的事实。

**信号**：当前值、实测、上线、已上线、MVP 上线、用户规模、日活、达标、✅、累计服务、已帮助……；英文里的 currently、in production、live、users、achieved。徽章（badge）里的数字也算。

**去哪找证据**：文档自己有没有说明「这是原型／练习／示例」；仓库里有没有后端代码、监控数据、上线记录；用户给的底稿里这个数字的来历。

**怎么判**：
- 仓库只有静态原型、没有数据来源，却写着「当前值」「已上线」→ 无据。
- 数字在原型页面里出现过，但文档没说明它是示例 → 无据（数字是真的，「实测」这个说法是假的）。
- 文档在显眼的位置声明了「示例数据」，并且离数字不远 → 有据。

**常见误报**：「目标 ≥ 85%」是目标，不是冒充实测；「上线后计划……」是计划。

## 2. 写了不存在的东西

**是什么**：提到的文件、目录、命令、链接、截图、许可证、功能，在仓库或材料里找不到。

**信号**：行内代码里的路径（`src/`、`index.html`）、目录树（`├──`）、安装和启动命令（`npm install`、`pip install -r requirements.txt`、`cp .env.example .env`）、相对链接、「见附件」「详见文档」、LICENSE 徽章。

**去哪找证据**：仓库文件清单。这一类优先交给 `scripts/check.py`，它比模型查得准。

**怎么判**：
- 文件清单里没有这个路径 → 无据。
- 命令依赖的文件不存在（`npm install` 却没有 `package.json`）→ 无据。
- 写了 MIT 许可证，却没有 LICENSE 文件 → 无据。
- 外部链接没法离线核对 → 存疑，标「未核」。

**常见误报**：示意性的伪代码、写给别人的「你可以这样部署」教程步骤（只要说清是给读者的操作，而不是声称仓库里已经有）。

## 3. 数字和引用没有出处

**是什么**：统计数字、行业数据、引用的话，说不出是从哪来的。

**信号**：据统计、研究表明、行业均值、超过 X% 的企业、调研显示、某某说过……；看起来很精确的数字（87.4%、13.2%）。

**去哪找证据**：文档里有没有脚注或链接；用户给的底稿里有没有这个数。

**怎么判**：
- 有链接或注明的来源，且来源在材料里 → 有据。
- 外部数据、不联网核不了 → 存疑，并建议补上出处。
- 用户自己的数据（自家产品的指标）却找不到来源 → 无据。

**常见误报**：常识性的数（一周七天）、文档自己定义的参数（「阈值设为 0.8」是设计，不是统计）。

## 4. 往大里说

**是什么**：数字被放大，用约数撑场面，用最高级的词。

**信号**：首个、唯一、领先、全面、彻底、零、100%、所有、近百、数十、上千、「半年」「多年」这类模糊的时长；英文里的 first、only、leading、all、zero、never。

**去哪找证据**：能算出来的就算：日期之间实际隔了多久，清单里实际有几项。

**怎么判**：
- 能算出来，而且算出来的比文中说的小 → 无据（比如共事不到三个月写成「半年」）。
- 最高级的词没有对比依据 → 存疑，建议降档。
- 有明确的统计口径，并且口径写在旁边 → 有据。

**常见误报**：口号和愿景句（「让每一天都在掌控之中」）不算事实陈述，跳过。

## 5. 能力越界

**是什么**：说支持某个能力，或者说接入了某个系统，材料里却没有任何证据。

**信号**：支持、兼容、已接入、对接、集成、自动、实时、可扩展到……

**去哪找证据**：代码、配置、接口文档、截图、测试记录。

**怎么判**：
- 是用户自己的产品，材料里完全找不到 → 无据。
- 写在「规划」「二期」「Roadmap」里 → 有据（说的是计划）。
- 写在「功能」里，但只在设计稿里出现过 → 存疑，建议改成「设计上支持」或「原型中演示」。

**常见误报**：第三方工具本身的能力（「Chart.js 支持动画」），不是在说自己的产品。

## 6. 前后对不上

**是什么**：同一件事在文档里两处说得不一样，或者和清单、表格对不上。

**信号**：页数、场景数、屏数、人数、版本号、日期在文中出现了不止一次；目录树和文件清单是两套名字。

**去哪找证据**：文档自身。`scripts/check.py` 会把同一个名词前后出现的不同数字列出来，供逐条核对。

**怎么判**：
- 两处数字不同，又没有解释 → 无据。
- 说了「共 16 个页面」，表格却只有 15 行 → 无据。
- 数字不同，但口径不同而且写明了（比如「首批 5 个、规划 12 个」）→ 有据。

**常见误报**：不同对象恰好用了同一个名词（「3 个角色」和「3 个角色卡片」）。
