## 四、要复核的判定

1. **M4 的边界判定**（影响结论档位）：旅行规划 B #14「仓库完整性（先核，必须改）」。B 组发现评测目录里只有 README，就把 LICENSE、requirements.txt、.env.example 等列为读不到，记为「必须改」。这几个恰好是干扰项 TPD1、TPD3、TPD4 对应的文件。但它明确写了「按派活单以清单为准，存在性检查通过」，「必须改」针对的是磁盘缺件，没有说 README 里的说法不实。所以我判为不算干扰项误报。如果改判为误报，B＝1 > A＝0，M4 不及格。
   - 预注册有个漏洞：只写了「M2、M3 不及格就不发布」，没写 M4 单独不及格怎么办。这一点我照实写出来，不替它补规则。
2. **B 组判得过重的一处**：记账 B #3，把「支持自定义列映射」和配置示例判成了「无据」。依据是底稿那句「config 里一项 currency」，可这句话也能读成「有一个 currency 配置项」，不一定是「只有一项」。按细则应判存疑。这一条不在答案里，不影响四项指标，但说明 B 组的判档还会偏重。
3. **计分人知情**：出题后我意外看到了座位预约 SB1 的答案片段（见 `计分人知情记录.md`）。两组都命中了 SB1，所以对 A、B 的对比没有影响。
