# 评测记录

这个 skill 测过两轮，每轮都是同一份文档分别「装 skill」和「不装 skill」各跑一次，再和事先冻结的标准答案对比。

| 轮次 | 模型 | 案例 | 结论 | 详细 |
|---|---|---|---|---|
| 第 1 轮 | Opus | 3 个真实 README 的改前版本 | 召回两组都是 20／20，看不出差别 | [results.md](results.md) |
| 第 2 轮 | Haiku | 3 个旧案例，加 3 个新出的、埋好问题的案例 | 召回 98% 比 100%，不及格；范围内占比 72% 比 91%，及格 | [round2/结果.md](round2/结果.md) |

## 文件

- `labels.json`：第 1 轮三个案例的标准答案，评测前提交。
- `runs/`：第 1 轮 6 份原始报告。
- `round2/预注册.md`：第 2 轮的指标、及格线和计分规则，评测前提交。
- `round2/cases/`：第 2 轮新出的 3 个案例，每个都有 README、文件清单、作者底稿。
- `round2/keys/`：新案例的标准答案，评测前封存。
- `round2/runs/`：第 2 轮 12 份原始报告。
- `round2/计分人知情记录.md`：计分人在计分前意外看到过的答案片段。

## 关于原始报告

- 报告是子代理的原文，只做了最小的脱敏：内部工单号和内部称呼换成了「评测单」「评测方」这类通用说法，其余一字未改。
- 报告里提到的 `/tmp/...` 目录是评测时临时搭的隔离目录。目录里只有要检查的文件，所以不少报告会写「某文件在清单里，但磁盘上没有」，这是评测环境造成的，不是案例本身的问题。

## 怎么复现

1. 照 `round2/预注册.md` 的设计，给每个案例建一个隔离目录，放入 README 和文件清单（新案例再加上底稿）。B 组另外放一份 `SKILL.md`、`references/`、`scripts/`。
2. 两组用同一句要求：「这份 README 发出去之前，帮他检查有没有不实、夸大、写错或者和仓库对不上的地方。」B 组再加一句「按 SKILL.md 的流程来」。
3. 拿报告和答案逐条对比，计分规则见预注册。
